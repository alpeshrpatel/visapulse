## Goal
Make the planner easier to use and share without changing what its rules conclude: show only relevant
fields, readable category names, a "Start over" control, a printable result, shareable state in the URL
fragment, and solid test coverage of the rules.

## Context
- Form: `src/GreenCardPlanner.jsx` (React). State object: `initialInput` (25 fields). Change handler: `updateInput`.
- Rules: `src/greenCardTimeline.js` → `buildGreenCardPlan(input, bulletin)`. Tests: `test/greenCardTimeline.test.js` (13 tests).
- Page shell and embedded data: `plannerPage` in `src/site/pages.js`; category entries come from `LINES` with `name` only.
- Styles: `src/client/planner.css`.

## Files to touch
`src/GreenCardPlanner.jsx`, `src/client/planner.css`, `src/site/pages.js` (embedded data), `src/site/site.css` (print),
`test/greenCardTimeline.test.js`, `test/site.test.js`.

## Steps
1. **Readable category labels.** In `plannerPage`, add `code: line.code` to each category entry. In the component, the
   category `<option>` text becomes `` `${category.code}: ${category.name}` `` (for example "EB-2: Advanced-degree professionals…").
   The option `value` stays the key.
2. **Only relevant fields.** Go through every field in the form and make sure it is rendered only when it applies:

   | Field(s) | Show when |
   |---|---|
   | PERM requirement, PERM status, premium processing | `route === 'employmentBased'` |
   | PERM status | additionally `permRequirement !== 'notRequired'` |
   | petitioner status, sponsor documents (`supportDocsReady`) | family routes |
   | category | not `familyImmediate` |
   | filing chart, biometrics, medical, interview (adjustment wording) | `path === 'adjustment'` |
   | consular stages | `path === 'consular'` |
   | cross-chargeability country | `crossChargeability` is ticked |
   | derivative birth date, petition filed/approved dates, processing location, transferred | inside a collapsed `<details>` "More details (optional)" |

   Compare with the current conditions first; change only what differs. A hidden field keeps its value in state.
3. **Start over.** A `<button type="button">Start over</button>` at the end of the form calls `setInput(initialInput)` and clears the fragment.
4. **Share through the fragment.** On every change write the fields that differ from `initialInput` to
   `location.hash` as `key=value&…` using `history.replaceState` (never the query string). On first render read the
   fragment and accept only keys that exist in `initialInput`, with values validated: dates by the
   `/^\d{4}-\d{2}-\d{2}$/` pattern, booleans as `true`/`false`, selects against their option values. Add a "Copy link" button
   that copies `location.href` (fallback: select a read-only input containing the URL).
5. **Print.** In `site.css` `@media print`: hide `.planner-form`; show the result block full width; keep the page's source
   line and footer disclaimer. Add a "Print this plan" button (`window.print()`), itself hidden in print.
6. **Designated chart (only if S-303 is done).** If `bulletin.designation` exists, preselect `filingChart` from it for the
   chosen route's group and show `Chart preselected from the USCIS announcement for <Month Year>` under the field. The visitor can still change it.
7. **Coverage.** Run `node --test --experimental-test-coverage test/greenCardTimeline.test.js` and read the line coverage
   for `src/greenCardTimeline.js`. Add tests for uncovered branches until it is ≥ 90%. Typical gaps: petition denied,
   consular `qualified` and `issued`, `approved` adjustment, PERM `notRequired`, invalid priority date, EB-5 fallback in
   `getCategory`. Each new test asserts `plan.nextStep.title` and `plan.nextStep.type`.
8. `npm run check`; verify in the preview at 375/768/1280, both themes.

## Pitfalls
- Do not change any rule text or branch in `greenCardTimeline.js` in this story. If you find a rule you think is wrong,
  log it; do not "fix" it.
- A priority date is personal information. It may appear in the fragment (which never reaches a server) but never in
  the query string, in analytics, or in any network request.
- `supportDocsReady` is `'unknown' | true | false`; serialise it as `unknown`, `true`, `false`.
- React controlled inputs: when restoring from the fragment, set state once in the `useState` initialiser, not in an effect loop.
