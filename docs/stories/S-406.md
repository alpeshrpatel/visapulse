## Goal
On bulletin day the owner has about an hour while search and community interest peaks. One command should
print everything needed to post: the month's summary, the changed lines, and ready-to-paste text for each
channel in `docs/growth/CHANNELS.md`. **The script posts nothing and makes no network request.**

## Usage
```bash
npm run bulletin:post -- 2026-12          # a period; default: the newest month in the data
SITE_URL=https://example.org npm run bulletin:post -- 2026-12
```

## Steps
1. `src/lib/postText.js` (`// @ts-check`), pure functions that take plain data and return strings:
   ```js
   /**
    * @param {{ label: string, previousLabel: string | null, verified: boolean, url: string,
    *           advances: number, retrogressions: number, unchanged: number,
    *           topAdvances: string[], topRetrogressions: string[], special: string[] }} facts
    * @returns {{ short: string, community: string, linkedin: string, messaging: string, changed: string }}
    */
   export function postTexts(facts)
   ```
   Templates (fill only from `facts`; when a list is empty write `none`):
   - `short` (≤ 270 characters):
     `<label> Visa Bulletin: <A> categories moved forward, <R> moved back, <U> unchanged (Final Action Dates). Full tables + history: <url>`
   - `community`:
     ```
     <label> Visa Bulletin is out.
     Final Action Dates vs <previousLabel>: <A> moved forward, <R> moved back, <U> unchanged.
     Biggest advances: <topAdvances joined with "; ">
     Moved back: <topRetrogressions joined with "; ">
     <one line per item in special>
     Full tables with the history of every category, each number checked against the official page: <url>
     I built this site. Not legal advice; confirm on travel.state.gov.
     ```
   - `linkedin`: the same facts in two short paragraphs, opening with
     `The <label> Visa Bulletin has been published.` and closing with
     `For HR and mobility teams: the tables and each category's history are at <url>.`
   - `messaging` (WhatsApp/Telegram, ≤ 500 characters): first two lines of `community` plus the link.
   - `changed`: a plain list, one line per changed pair: `<code> <area>: <old> → <new> (<label>)`.
   When `verified` is false, every text ends with `Data for this month is not yet verified against the official page.`
   and the script prints a warning: do not post unverified numbers.
2. `scripts/bulletin-post.mjs`: load the dataset (`loadDataset`, both directories as `build-site.mjs` does), take the
   period argument (validate with `isPeriod`; unknown period → exit 2 with a message), compute `summariseMovement`,
   build `facts` (top three of each list as `"<code> <area> <movement.label>"`; `special` from moves whose label is
   `Became current`, `Became unavailable`, `Cut-off imposed`, `Available again`), set
   `url = (SITE_URL ?? 'https://YOUR-SITE') + urls.bulletin(period)`, and print each text under a heading line
   such as `=== Short (X, Bluesky, Mastodon) ===`. If `SITE_URL` is unset print a warning first.
3. `docs/RUNBOOKS.md`: add **RB9 Bulletin day** — the checklist from `docs/growth/CHANNELS.md` section "Bulletin day"
   in six numbered lines, ending with "Run `npm run bulletin:post` and paste; never post before step 3 of RB2 (spot check) is done."
4. `npm run check`; run the command for `2025-06` and read the output.

## Pitfalls
- "I built this site" is required in community text: undisclosed self-promotion gets accounts banned and is dishonest.
- Do not add hashtags, emojis or superlatives. The text must stay factual so it survives moderation.
