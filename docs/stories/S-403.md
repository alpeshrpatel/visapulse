# S-403 Privacy-friendly analytics (off by default)

| | |
|---|---|
| Status | READY |
| Size | S |
| Difficulty | Routine |
| Phase | 3 Launch |
| Needs | nothing (choosing a provider and creating the account is an owner action) |
| Unblocks | S-410, and every measurement in `docs/growth/METRICS.md` |

## Goal
Let the owner switch on a cookieless analytics script by setting build-time variables, for any provider.
When the variables are unset, **nothing** is added to any page.

## Settings
| Variable | Meaning | Rule |
|---|---|---|
| `ANALYTICS_SCRIPT_URL` | Address of the provider's script | must be `https:`; otherwise ignored |
| `ANALYTICS_ATTRIBUTES` | Optional JSON object of extra attributes for the script tag, e.g. `{"data-domain":"example.org"}` | every key must match `^data-[a-z0-9-]+$`; every value a string of at most 200 characters; anything else makes the build **fail** with a clear message |

Examples the owner may use later (do not hard-code any provider): Plausible uses `data-domain`; Cloudflare Web Analytics
uses `data-cf-beacon`; GoatCounter uses `data-goatcounter`.

## Files to touch
`scripts/build-site.mjs`, `src/site/layout.js`, `src/site/pages.js` (privacy page), `.env.example`, `test/site.test.js`,
`docs/RUNBOOKS.md` (RB4).

## Steps
1. `scripts/build-site.mjs`: add a function `analyticsConfig(env)` that returns
   `{ src: string, attributes: Record<string, string> } | null` following the table (reuse `publicUrl` for the https check
   but keep the full URL, not just the origin; reject `localhost`). Put the result on `site.analytics`. Print
   `analytics: on (<host>)` or `analytics: off` in the build report.
   Move the function to `src/site/config.js` (new, pure, takes the env object as a parameter) so it can be unit-tested.
2. `src/site/layout.js`: add `analytics: { src: string, attributes: Record<string, string> } | null` to `SiteContext`.
   Before `</head>` emit, only when set:
   ```js
   ${site.analytics ? html`<script defer src="${site.analytics.src}"${Object.entries(site.analytics.attributes).map(([name, value]) => html` ${raw(name)}="${value}"`)}></script>` : ''}
   ```
   `raw(name)` is safe **only** because the name was validated against the pattern; add that comment in the code.
3. Privacy page (`staticPages` in `src/site/pages.js`): when `site.analytics` is set add the bullet
   "**Visit statistics:** we count page views with a cookieless analytics service (`<host of the script>`). It sets no
   cookies, builds no profile and does not follow you across sites. What you type into the checker or planner is never
   included." and change the opening sentence so it no longer says "no third-party scripts". When unset, the page is unchanged.
4. `.env.example`: add both variables, empty, each with a one-line comment.
5. `docs/RUNBOOKS.md` RB4: add the two variables to the environment list.
6. `npm run check`.

## Tests to add
- `analyticsConfig({})` → null; http URL → null; valid URL without attributes → `{ src, attributes: {} }`;
  attributes with a bad key (`onload`) → throws; with a non-string value → throws; invalid JSON → throws.
- `test/site.test.js`: add `analytics: null` to the `site` fixture. A page rendered with the default fixture contains no
  `<script` tag other than the theme script, the JSON blocks and the site assets (assert the page does not include
  `data-domain` and that the count of `<script` matches the count before this story). A page rendered with
  `analytics: { src: 'https://stats.example.org/s.js', attributes: { 'data-domain': 'example.org' } }` contains
  `<script defer src="https://stats.example.org/s.js" data-domain="example.org"></script>`, and the privacy page mentions `stats.example.org`.

## Acceptance
- [ ] With no variables set, the built HTML is byte-for-byte free of any analytics markup (test proves it).
- [ ] With the variables set, every page carries the one script tag with the given attributes, HTML-escaped.
- [ ] Invalid attribute names or values stop the build with a message naming the variable.
- [ ] The privacy page describes the analytics only when it is on.
- [ ] `.env.example` and RUNBOOKS document the variables. No provider name or account id is hard-coded.
- [ ] `npm run check` green.

## Pitfalls
- No personal identifiers: do not add the page fragment, the checker's inputs or any custom event that carries what a
  visitor typed. This story adds page-view counting only.
- The script loads from a third party, so the "no third-party requests" claim on the privacy page stops being true when
  it is on: that is why step 3 is part of the story.

## Owner action to log
"Pick a cookieless analytics provider, create the site there, and set `ANALYTICS_SCRIPT_URL` (and `ANALYTICS_ATTRIBUTES`)
in the host's build settings." See `docs/growth/METRICS.md` for what to look at.
