| | |

| Why (growth) | In the days before each release people repeatedly search whether the next month's bulletin is out. A page with a clear yes/no, updated on every deploy, earns that visit and offers the alert sign-up. See `docs/growth/SEO.md`, page type P8. |

## Goal
`/next-visa-bulletin/` answers one question: has the next month's bulletin been added here yet? It states
only facts we hold: the newest month in our data, when we added recent months, and where to look officially.
It never says when a bulletin "will" come out.

## Part 1 — record when a month was added
`scripts/fetch-archive.mjs` writes manifest entries. Add a field `addedOn` (ISO date, UTC, the day the script ran):
- set it **only when a new entry is created for a period that is the current calendar month or later** (bulletins are
  added in the month before they take effect, so this is true for genuinely new months and false for the historical backfill);
- never change an existing `addedOn`; `--refresh` keeps it;
- the same rule for `--file` (manual) entries.
Put the rule in a pure helper `shouldStampAddedOn(period, today)` in `src/lib/freshness.js` (create the file if S-111
has not) with tests: `('2026-12', '2026-11-16')` true; `('2026-11', '2026-11-16')` true; `('2026-10', '2026-11-16')` false;
`('2003-06', '2026-11-16')` false.
The record files in `data/bulletins/` do **not** gain this field (so no record changes).

## Part 2 — the page
`nextBulletinPage({ site, dataset, manifest })` at `urls.nextBulletin = '/next-visa-bulletin/'`:
- `latest = dataset.latestPeriod`; `upcoming = shiftPeriod(latest, 1)`.
- `<h1>Is the <Upcoming Month Year> Visa Bulletin out?</h1>`
- Answer box: "**Not in our data yet.** The newest bulletin here is <a>`<Latest Month Year>`</a>" +
  (when its manifest entry has `addedOn`) ", added on `<date>`" + "."
- "Check the official source": link to `OFFICIAL_LINKS.bulletinIndex` — "The State Department posts each bulletin on
  its own site first. If it shows `<Upcoming Month Year>` and we do not, we are checking it and will add it shortly."
- "Get told": link to `/alerts/` (only when `site.hasFeed`).
- "When recent bulletins were added here": a table of up to 12 newest periods that **have** `addedOn`: Bulletin, Added
  here on. Under it: "These are the dates VisaPulse added each month, not official release dates." If no period has
  `addedOn` yet, omit the table.
- Closing `muted` line: "We do not predict release dates."
- Title: `Is the <Upcoming Month Year> Visa Bulletin out yet?`
  Description: `Whether the <Upcoming Month Year> Visa Bulletin has been published and added to VisaPulse. Newest
  bulletin here: <Latest Month Year>. Link to the official source and alerts.`

## Pitfalls
- `validate-data.mjs` reads only `sha256` from manifest entries; an extra field is safe. Confirm by running it.
- Never write `addedOn` by hand into the manifest for past months "to fill the table".
- When the data is far behind (before the owner's backfill and S-110), "upcoming" may be a month that is long past.
  If `upcoming` is earlier than today's month, the page says instead: "Our data is behind: the newest bulletin here is
  <Latest Month Year>. See the official site for newer bulletins." The build passes today's date in; the renderer takes it as a parameter.
