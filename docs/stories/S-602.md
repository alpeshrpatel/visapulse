## Goal
An HR team or a law office tracks dozens or hundreds of people. `/watchlist/` lets them paste or load a CSV
of cases and see, for the latest bulletin, who is current on each chart and what changed since last month.
**Everything stays in the browser**: no upload, no account. This is the feature most likely to be worth
paying for later (S-607), so it must be trustworthy first.

## CSV format (documented on the page)
Header row required, column order free, names case-insensitive:
`label, category, area, priority_date`
- `label`: free text up to 80 characters (an internal reference; the page advises "use a case number, not a name").
- `category`: a line code or slug: `EB-2`, `EB2`, `eb2`, `F4`, `EB-3 Other Workers`, `eb3-other-workers`, …
- `area`: `All`, `ROW`, `All Chargeability`, `China`, `India`, `Mexico`, `Philippines` (or the slug).
- `priority_date`: `YYYY-MM-DD` (also accept `MM/DD/YYYY`; reject anything ambiguous or impossible).
Limit: 2,000 data rows. Fields may be quoted with `"`; `""` is an escaped quote; commas inside quotes are allowed.

   Error reasons are fixed strings: `missing header "<name>"`, `unknown category "<value>"`, `unknown area "<value>"`,
   `invalid priority date "<value>"`, `priority date is in the future` (the caller passes `today`), `label too long`,
   `more than 2,000 rows (rows after 2,000 ignored)`.
   **CSV injection:** when exporting, prefix any field that starts with `=`, `+`, `-` or `@` with a single quote `'`.
2. `assessRow` uses `priorityDateStatus` for the latest month and the previous month on each chart:
   result per chart `{ cutoff, status, statusLastMonth, changed: 'became current' | 'no longer current' | 'no change' | 'no data' }`.
3. `watchlistPage({ site, dataset })`: hero (`<h1>Watchlist: check many priority dates at once</h1>`), the statement
   "Your list never leaves this device. This page makes no network request with your data; you can turn off your
   connection after it loads and it still works.", a `<textarea>` to paste CSV, a file input (`accept=".csv,text/csv"`),
   a "Load an example" button (five invented rows with labels `Example 1`…), filter controls (All / Current on Final
   Action / Current on Dates for Filing only / Not current / Changed this month), the result table region, "Download
   CSV", the checkbox "Remember this list on this device" with a "Forget saved list" button, and the usual
   "what this does not tell you" list (copy the four bullets from the checker page).
   Embed JSON `{ period, periodLabel, previousPeriod, verified, today, lines, areas, cutoffs }` where each cut-off entry
   is `{ now, prev }` (previous month via `shiftPeriod(latest, -1)`; absent when that month is missing).
4. `src/client/watchlist.js`: imports the pure functions; renders with `createElement` only; reads files with
   `FileReader`; table columns: Label, Category, Area, Priority date, Final Action (cut-off + status), Dates for Filing
   (cut-off + status), Change since <previous month>; a list of rejected rows with their reason above the table;
   local storage key `visapulse-watchlist` used **only** when the checkbox is ticked, removed by the forget button and
   when the box is unticked.
5. Register the page and the script (`watchlistJs`); link it from the checker page ("Checking many dates? Use the
   watchlist") and the footer. `npm run check`.

## Acceptance
- [ ] Paste or load up to 2,000 rows; each row shows its status on both charts for the latest bulletin and the change since the previous month.
- [ ] Filters work; "Download CSV" exports the visible table safely (injection prefix).
- [ ] Bad rows are listed with the row number and reason; good rows still show.
- [ ] No network call carries the data (source check test + the network panel shows no request after load).
- [ ] "Remember on this device" is off by default, uses local storage only when ticked, and can be cleared.
- [ ] A date equal to the cut-off is "not current".
- [ ] `npm run check` green; 375 and 1280, light and dark; 2,000 rows render without the page freezing for more than about a second.

## Pitfalls
- Labels are other people's information. Render them with `textContent` only; never as HTML.
- Do not send anything to analytics from this page beyond the page view.
- A 2,000-row table needs the usual `.table-scroll` wrapper; do not build a virtual list.
