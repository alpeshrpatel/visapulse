## Goal
Serve the most-used pages in Spanish (`/es/`), Hindi (`/hi/`) and Simplified Chinese (`/zh/`): home, checker,
priority-dates index and disclaimer. A language goes live only after a fluent person has approved the
disclaimer and checker wording. A wrong translation of a legal caution is worse than no translation.

## Design
- One string catalog per language: `src/i18n/en.js`, `es.js`, `hi.js`, `zh.js`, each exporting a flat object
  `{ 'home.kicker': 'Visa Bulletin · Fiscal year {year}', … }`.
- `t(locale, key, values)` in `src/i18n/index.js` replaces `{name}` placeholders. Missing key in a non-English catalog:
  in development (`SHOW_DRAFTS=1`) it returns the English text wrapped as `⟦…⟧`; in a normal build for a **published**
  language it throws and fails the build.
- `src/i18n/languages.js`: `[{ code: 'es', name: 'Español', dir: 'ltr', reviewedOn: null, reviewer: null }, …]`.
  A language with `reviewedOn: null` is built only with `SHOW_DRAFTS=1` and with `noindex`.
- Dates: `Intl.DateTimeFormat(locale, { year: 'numeric', month: 'long', day: 'numeric', timeZone: 'UTC' })` so the month
  is a word and the order cannot be misread. Never print `01/02/2013`.
- Category codes (`EB-2`, `F4`), `Current`/`Unavailable` (translated through the catalog, with the English term in
  brackets on first use) and country names (through the catalog).

## Files to touch
`src/i18n/*` (new), `src/site/layout.js` (locale parameter, `<html lang>`, `hreflang` links, language switcher),
`src/site/pages.js` (the four page renderers take `locale`), `src/site/format.js` (`localePath(locale, path)`),
`src/client/check.js` (strings come from the embedded JSON, not hard-coded), `scripts/build-site.mjs`,
`test/i18n.test.js` (new), `test/site.test.js`.

## Steps
1. Extract every visible string of the four pages and the shared layout into `en.js`. The English output must be
   **byte-identical** to before (compare `dist/index.html` before and after with `diff`). Do this first, alone, and run `npm run check`.
2. Add `t`, `languages.js`, and the missing-key behaviour with tests.
3. Thread `locale` through `layout`, `bulletinPage` (home only), `linesIndexPage`, `checkPage` and the disclaimer page.
   Internal links on a translated page point to the translated version when it exists, otherwise to English.
4. `hreflang`: on each of the four pages emit `<link rel="alternate" hreflang="…" href="…">` for English, every
   **published** language and `x-default` (English). Only when `SITE_URL` is set.
5. Language switcher in the header: a `<nav aria-label="Language">` list of published languages (each link has `lang`
   and `hreflang` attributes). Hidden entirely when no other language is published.
6. Draft catalogs for `es`, `hi`, `zh`: you may write a first-draft translation, clearly marked at the top of each file
   `// DRAFT machine-assisted translation. Not reviewed. Do not publish.` Keep legal sentences literal.
7. Build: for each language that is published (or all, with `SHOW_DRAFTS=1`), write the four pages under `/<code>/…`.
8. Create `docs/i18n/REVIEW.md`: instructions for a human reviewer — which pages to read (run with `SHOW_DRAFTS=1`),
   the list of sentences that carry legal weight (disclaimer, "earlier than", "not a forecast", "not legal advice"),
   and how to sign off (set `reviewedOn` and `reviewer` in `languages.js`).

## Tests to add
- English output unchanged for the four pages (snapshot of `<h1>` and the disclaimer sentence is enough).
- Every key in `en.js` exists in each other catalog (test fails listing missing keys) — applies to published languages;
  for drafts the test prints a count but does not fail.
- A published language with a missing key makes `t` throw.
- Unpublished languages produce no pages and no `hreflang` in a normal build.
- Date formatting in each locale contains the year and no `/`.

## Acceptance
- [ ] All interface strings of the four pages come from one catalog; English pages are unchanged.
- [ ] `/es/`, `/hi/`, `/zh/` versions build from catalogs when the language is published or drafts are shown.
- [ ] `hreflang` and the language switcher list published languages only.
- [ ] Missing translation: visible fallback in development, build failure for a published language.
- [ ] No language is published by an agent (`reviewedOn` stays null); `docs/i18n/REVIEW.md` exists.
- [ ] `npm run check` green in the normal build and with `SHOW_DRAFTS=1`.

## Pitfalls
- Hindi and Chinese need fonts the visitor's device already has; do not add web fonts.
- Do not translate URLs of categories or the data files.
- The checker's script currently has English sentences inside `check.js`. They must move into the embedded JSON or the
  translated pages will mix languages.
