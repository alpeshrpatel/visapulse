# S-706 PERM timing context for employment cases

| | |
|---|---|
| Status | BLOCKED until S-701 gives a GO for the Department of Labor source |
| Size | M |
| Difficulty | Careful |
| Phase | 6 Insight |
| Needs | S-701 `DONE` with a GO for DOL PERM processing times; S-703 `DONE` (the DOL link-out) |

## Goal
For employment cases the first long step is the employer's labor certification (PERM). The Department of
Labor publishes which filing month it is currently working on. Show that published date in the planner's
labor-certification step, with its "as of" date and a link — updated by a documented monthly step. If the
source is a NO-GO, this story is dropped and the S-703 link-out is the final answer.

## Design
- Data file `data/dol-perm-times.json`, entered by a person (the same pattern as S-303's USCIS designation):
  ```json
  { "asOf": "2026-11-01",
    "sourceUrl": "https://flag.dol.gov/processingtimes",
    "checkedOn": "2026-11-16",
    "analystReview": { "priorityDateMonth": "2025-06" },
    "auditReview":   { "priorityDateMonth": "2025-01" } }
  ```
  The exact field names must follow what the DOL page actually publishes (S-701 records that). Create the file as `{}`.
- Validator `validatePermTimes` in `src/lib/permTimes.js`: `{}` is valid; otherwise every field required, dates real,
  months valid periods, `sourceUrl` host ends in `.dol.gov`.

## Steps
1. Read `docs/data/SOURCES.md` for what the DOL page publishes and adjust the field names above to match. Do not add a
   field the page does not publish.
2. Create the data file as `{}`, the validator with tests, and wire it into `scripts/validate-data.mjs`.
3. `plannerPage`: add the object (when not empty) to `plannerBulletin`.
4. Planner: in the labor-certification stage (shown when the route is employment-based and PERM is required or unknown),
   when data exists show: "The Department of Labor reports it is processing applications filed in <Month Year>
   (as of <asOf>)." + the source link + "This is the agency's published status, not an estimate for your case."
   When the file is `{}`, show only the S-703 link.
5. `docs/RUNBOOKS.md` RB2: add step 7: "Open the DOL processing-times page; update `data/dol-perm-times.json` with the
   published months and today's date in `checkedOn`."
6. Tests: validator cases; the planner page's embedded JSON has no `permTimes` key when the file is `{}`, and has it with a synthetic entry.
7. `npm run check`. Remove any synthetic entry before finishing.

## Acceptance
- [ ] `data/dol-perm-times.json` exists as `{}`; no value entered by an agent from memory.
- [ ] Validator rejects malformed entries and non-DOL sources; runs in `npm run data:validate`.
- [ ] The planner shows the published processing month with its "as of" date and link when data exists, and only the link otherwise.
- [ ] RUNBOOKS has the monthly update step.
- [ ] `npm run check` green.

## Pitfalls
- Do not compute "your PERM will be decided in N months". Show the agency's sentence-level fact only.
- If the owner gives you the values with the page address, enter exactly those and set `checkedOn` to that day.
