## Goal
Each month USCIS announces which chart people filing for adjustment of status (Form I-485) must use:
Final Action Dates or Dates for Filing, separately for family-sponsored and employment-based cases. This is
the most asked question after "did my date move". Build the place for that fact (a data file, a validator,
and the wording on pages). **You will not enter any real month**: entries are typed by a person reading the
official USCIS page. Until an entry exists, pages say "check USCIS" with the link.

## Data file
`data/uscis-filing-charts.json` — an object keyed by period. Create it as `{}`.
```json
{
  "2026-12": {
    "family": "datesForFiling",
    "employment": "finalActionDates",
    "sourceUrl": "https://www.uscis.gov/…",
    "checkedOn": "2026-11-18"
  }
}
```
Allowed values for `family` and `employment`: `finalActionDates`, `datesForFiling`.

## Steps
1. `src/lib/filingCharts.js` (`// @ts-check`):
   ```js
   /** @typedef {{ family: Chart, employment: Chart, sourceUrl: string, checkedOn: string }} Designation */
   /** @param {unknown} data @returns {string[]} problems; empty means valid */
   export function validateFilingCharts(data)
   /** @param {Record<string, Designation>} data @param {string} period @returns {Designation | null} */
   export function designationFor(data, period)
   ```
   Validation rules: the top level is a plain object; every key passes `isPeriod` and is `>= '2015-10'`; `family` and
   `employment` are one of the two allowed values; `sourceUrl` starts with `https://www.uscis.gov/`; `checkedOn` is a real
   ISO date (reuse `isIsoDate` from `./validateBulletin.js`; do not compare it with today, because `src/lib` never reads
   the clock); no other keys.
2. `scripts/validate-data.mjs`: read the file (missing file = error), run `validateFilingCharts`, push each problem into
   `errors` prefixed with `uscis-filing-charts.json: `. Add the entry count to the final "Data valid" line.
3. `scripts/build-site.mjs`: read the file once and pass `filingCharts` to every page function that takes `{ site, dataset }`
   (add it to the `Common` typedef in `src/site/pages.js` as optional, default `{}`).
4. `src/site/components.js`: export `filingChartNote(designation, period, group?)`:
   - with a designation:
     `For <Month Year>, USCIS says adjustment of status applicants use the <chart name> chart for family-sponsored cases and the <chart name> chart for employment-based cases.`
     followed by a link "USCIS announcement" (`designation.sourceUrl`) and `Checked <formatted checkedOn>.`
     When `group` is given, mention only that group.
   - without: `Which chart USCIS accepts for <Month Year> is not recorded here yet.` plus a link
     "Check the USCIS page" (`OFFICIAL_LINKS.uscisCharts`).
   Wrap both in `<p class="uscis-note">`.
5. Use it:
   - `bulletinPage`: in the Dates for Filing panel help text, replace the sentence that ends with the "Check which chart…"
     link by `filingChartNote(designation, period)`. Only months with a filing chart show it.
   - `lineAreaPage`: replace the sentence "Whether the Dates for Filing chart can be used…" with the note for the latest
     period and the line's group.
   - `checkPage`: add `designation` (or `null`… use an absent key, not the word null in visible text) to the embedded data
     and the note under the hero. In `src/client/check.js`, when a designation exists, add the class `stat-card-designated`
     and the line `USCIS accepts this chart for adjustment of status filing this month.` to the card of the designated chart
     for the selected line's group (the script needs each line's `group`; add it to `data.lines`).
   - `plannerPage`: add `designation` to `plannerBulletin` (unused until S-304) and show the note under the hero.
6. `site.css`: `.uscis-note` like `.source-line`; `.stat-card-designated { border-color: var(--accent); }`.
7. Methodology page, "Limits" paragraph: change "We do not yet show which chart USCIS accepts each month" to
   "We show which chart USCIS accepts only for months where a person has recorded it from the USCIS page; otherwise we link there."
8. `npm run check`.

## Pitfalls
- **Do not enter real data.** uscis.gov blocks scripts, and a designation recalled from memory is a guess. If the owner
  gives you a month's values with the URL, enter exactly those.
- Remove any synthetic entry you used for testing before finishing; `git diff data/uscis-filing-charts.json` must show `{}`.
- The built-site check rejects the visible words `null` and `undefined`. Leave the key out when there is no designation.
