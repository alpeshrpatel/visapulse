## Goal
A visitor who knows what they want ("EB-2 India", "F4 Philippines", "June 2025") should get there in one
step from the home page and from the priority-dates index, by typing into one labeled box.

## Design (implement exactly this)
- A native text input with a `<datalist>`: the browser provides the suggestion list, keyboard handling and
  screen-reader support. No custom dropdown.
- The widget is created by JavaScript. With JavaScript off the page is unchanged (the container stays `hidden`).
- On submit (Enter) or when the typed value exactly matches an option, the browser navigates to that page.
- Data is embedded once as compact JSON; labels are built in the browser.

## Files to touch
`src/site/components.js`, `src/site/pages.js`, `src/client/site.js`, `src/site/site.css`, `test/site.test.js`.

## Steps
1. `src/site/components.js`: export `jumpBox(dataset)` returning
   ```html
   <form class="jump" data-jump hidden role="search" aria-label="Jump to a category or month">
     <label for="jump-input">Jump to a category, country or month</label>
     <input id="jump-input" name="q" type="search" list="jump-options" autocomplete="off"
            placeholder="EB-2 India, F4 Philippines, June 2025">
     <datalist id="jump-options"></datalist>
     <button type="submit">Go</button>
     <p class="jump-status" role="status" aria-live="polite"></p>
     <script type="application/json" data-jump-data>…</script>
   </form>
   ```
   The JSON (through `jsonForScript`) is
   `{ lines: [[code, slug], …], areas: [[name, slug], …], periods: [ 'YYYY-MM', … ] }` built from `LINES`, `AREAS`
   and `dataset.periods`.
2. `src/site/pages.js`: put `${jumpBox(dataset)}` in the hero section of the home page (`bulletinPage` when `isHome`)
   directly after the call-to-action row, and in the hero of `linesIndexPage`.
3. `src/client/site.js`: add a block (same style as the existing ones):
   - find `[data-jump]`; if absent, return;
   - parse the JSON; build a `Map` from lower-cased label → path:
     - `"<code>"` → `/priority-dates/<lineSlug>/` (15 entries);
     - `"<code> <areaName>"` → `/priority-dates/<lineSlug>/<areaSlug>/` (75 entries);
     - `"<Month> <Year>"` → `/visa-bulletin/<month>-<year>/` (one per period; month names from a 12-item array in the script);
   - append one `<option value="<label>">` per entry to the datalist, in that order;
   - on `submit`: `preventDefault()`, look up `input.value.trim().toLowerCase()`; if found `location.assign(path)`,
     else set the status text to `No page matches "<what was typed>". Pick one from the list.`;
   - on `change` of the input: if the value matches, navigate (this is what fires when an option is chosen);
   - finally remove the `hidden` attribute.
4. `site.css`: `.jump { display: flex; flex-wrap: wrap; gap: 8px; align-items: end; margin-top: 16px; }`,
   label on its own line (`flex-basis: 100%`), input `flex: 1 1 220px; min-width: 0;` with the same border, radius and
   padding as `.feedback-form input`, button styled like `.button`. It must not cause horizontal scrolling at 375 px.
5. `npm run check`; then test in the preview.

## Tests to add (`test/site.test.js`)
- The home page and the lines index contain `data-jump` and `hidden`.
- The embedded JSON parses; `lines.length === LINES.length`; `areas.length === AREAS.length`;
  `periods` equals `dataset.periods`.
- A bulletin page that is not the home page does **not** contain `data-jump`.

## Acceptance
- [ ] Box appears on `/` and `/priority-dates/` only, and only when JavaScript runs.
- [ ] Typing `EB-2 India` + Enter opens `/priority-dates/eb2/india/`; `june 2025` opens `/visa-bulletin/june-2025/`; `F4` opens `/priority-dates/f4/`.
- [ ] An unknown entry shows the status message and does not navigate.
- [ ] Works with the keyboard alone; the input has a visible label and focus ring.
- [ ] Embedded data is under 4 kB gzip (measure: the home page gzip size before and after, both printed by `npm run build`).
- [ ] No horizontal scroll at 375 px; light and dark checked.
- [ ] `npm run check` green.

## Pitfalls
- The built-site check counts `<h1>` elements: do not add a heading inside the form.
- Do not use `innerHTML` to fill the datalist; create `option` elements.
- A month that is withheld has no page. Only `dataset.periods` go into the list, so every option resolves.
- Matching is exact (case-insensitive). Do not add fuzzy search; the datalist already filters as the visitor types.
