## Goal
`/compare/` lets a visitor put up to five lines (category × area) on one chart, for one chart type, with a
legend, a data table and a CSV download. Typical use: "EB-2 India against EB-3 India", "F4 for all areas".

## Design (implement exactly this)
- The build writes one small JSON file per line × area: `/data/series/<lineSlug>/<areaSlug>.json`
  ```json
  { "line": "EB2", "area": "india", "label": "EB-2 India",
    "finalActionDates": [["2002-01", "Current"], ["2002-02", "2001-05-01"]],
    "datesForFiling":   [["2015-10", "2011-07-01"]] }
  ```
- The page is a static form (five line pickers + a chart picker) and an empty result region.
- The browser script fetches the selected files (same origin, static), draws the chart with the **same**
  `renderCutoffChart` used at build time, and builds the legend and table.
- Selection lives in the URL fragment: `#lines=eb2.india,eb3.india&chart=final-action`.

## Files to touch
`src/site/format.js` (`urls.compare`), `src/site/pages.js` (`comparePage`), `src/client/compare.js` (new),
`scripts/build-site.mjs`, `src/site/layout.js` (typedef + optional nav), `src/site/site.css`, `test/site.test.js`,
`src/site/pages.js` open-data text.

## Steps
1. `scripts/build-site.mjs`, in the open-data section: for each `LINES` × `AREAS` write the JSON file above from
   `dataset.series(...)` (map each point to `[period, value]`). Add `compare: 'src/client/compare.js'` to `entryPoints`
   and `compareJs` to `site.assets`; add `compareJs?: string` to the `SiteContext` typedef.
2. `urls.compare = '/compare/'`. `comparePage({ site, dataset })`:
   - hero: `<h1>Compare priority-date histories</h1>`, lede "Put up to five categories and countries on one chart.
     This shows what happened; it is not a forecast.";
   - `<form id="compare-form">` with five `<select name="line1">…<select name="line5">`. Each has a first option
     `value=""` labelled "None" and then one `<optgroup>` per group with options `value="<lineSlug>.<areaSlug>"`
     text `"<code> <area name>"`; `line1` defaults to `eb2.india`, `line2` to `eb3.india`;
   - a chart `<select name="chart">` with the two `CHARTS` (`value` = `slug`);
   - `<section id="compare-result" aria-live="polite">` containing a `<noscript>` note linking to `/priority-dates/`;
   - the `explain` list: cut-offs are as published; gaps are months not in our data; not a forecast;
   - `head: html`<script src="${site.assets.compareJs}" defer></script>``.
   Register the page in `build-site.mjs`. Link to it from `linesIndexPage` (one sentence under the tables) and from the
   "Related" block of `lineAreaPage` ("Compare <name> with another category").
3. `src/client/compare.js`:
   ```js
   import { renderCutoffChart } from '../site/chart.js'
   ```
   - read the fragment into the form (validate every value against the option lists);
   - on `input`: collect the distinct non-empty selections (max five), `fetch('/data/series/<line>/<area>.json')` each
     (cache results in a `Map`), build `series = [{ name: label, color: index + 1, points: [{ period, value }] }]` for the
     chosen chart;
   - render: a legend (`<ul class="chart-legend">` as on other pages), the chart, a table (rows = periods descending,
     one column per series, values through the same date formatting as `check.js`), and a "Download CSV" button;
   - the chart function returns an SVG **string** this code base produced. Insert it by parsing:
     `new DOMParser().parseFromString(String(svg), 'image/svg+xml').documentElement`, then `append` the node.
     Do not assign `innerHTML`;
   - CSV: header `period,<label 1>,<label 2>…`, one row per period, values as stored; download through
     `URL.createObjectURL(new Blob([csv], { type: 'text/csv' }))` and a temporary `<a download="visapulse-compare.csv">`;
   - write the fragment with `history.replaceState`;
   - on a fetch error show `Could not load <label>. Check your connection and try again.`
4. `site.css`: `#compare-form` as a wrapping grid (one column under 640 px); reuse `.chart-scroll`, `.table-scroll`.
5. Open-data page: add a bullet for `/data/series/<category>/<area>.json`.
6. `npm run check`; then test in the preview.

## Tests to add (`test/site.test.js`)

- A helper exported from the build or a small pure function `seriesFile(dataset, line, area)` (put it in

## Acceptance
- [ ] `/compare/` draws one to five lines on one SVG with a legend and a data table.
- [ ] The selection survives a reload through the fragment; nothing is put in the query string.
- [ ] "Download CSV" produces exactly the plotted values.
- [ ] Works at 375 px without the page scrolling sideways (the chart scrolls inside its box).
- [ ] The chart code is the shared `renderCutoffChart` (no second chart implementation).
- [ ] With JavaScript off the page explains itself and links to the static pages.
- [ ] `npm run check` green (75 new JSON files resolve); compare script size reported in the logbook.

## Pitfalls
- Only five series colours exist (`--series-1` … `--series-5`). Enforce the limit of five.
- `renderCutoffChart` needs at least two points in total, otherwise it returns the "Not enough history" paragraph (an
  HTML string, not SVG): handle that case by showing the text.
- `src/client/` is not type-checked. Test every path in the browser, including choosing the same line twice.
- Internal links are checked by `check-site`: link to `/compare/` only after the page is registered in the build.
