# S-503 Subscribe interface

| | |
|---|---|
| Status | READY after S-501 |
| Size | M |
| Difficulty | Careful |
| Phase | 4 Alerts and retention |
| Needs | S-501 `DONE` (the API contract). S-504 `DONE` (the `/alerts/` page hosts the form too). |

## Goal
A small sign-up form for email alerts, shown only when the site is built with the API address. It must be
honest about what is stored and must never be the only way to follow the bulletin.

## Settings
| Variable | Meaning |
|---|---|
| `ALERTS_API_URL` | Base address of the S-501 service (https). Unset → no form anywhere. |
| `ALERTS_CHALLENGE_SITE_KEY` | Public site key for the bot challenge widget. Unset → no form anywhere. |

## Files to touch
`scripts/build-site.mjs`, `src/site/layout.js` (typedef), `src/site/components.js` (`subscribeForm`), `src/site/pages.js`,
`src/client/subscribe.js` (new), `src/site/site.css`, `.env.example`, `test/site.test.js`, `public/_headers` (only if a
Content-Security-Policy is added later; not in this story).

## Steps
1. Build settings (recipe 7.4 in the stories README): `site.alerts = { apiUrl, challengeSiteKey } | null`; both must be present.
2. `subscribeForm({ site, line, area })` in `src/site/components.js` returns nothing when `site.alerts` is null, else:
   ```html
   <section class="subscribe" aria-labelledby="subscribe-h">
     <h2 id="subscribe-h">Email me when this changes</h2>
     <form data-subscribe data-api="…" novalidate>
       <label>Email address <input type="email" name="email" required autocomplete="email" maxlength="254"></label>
       <!-- category and area: hidden inputs when the page is about one line and area; selects otherwise -->
       <label>Chart <select name="chart"><option value="both">Both charts</option><option value="finalActionDates">Final Action Dates</option><option value="datesForFiling">Dates for Filing</option></select></label>
       <label>Priority date (optional) <input type="date" name="priorityDate" min="1970-01-01"></label>
       <p class="consent">We will send one confirmation email. After you confirm, we email you only when this cut-off
         changes or your priority date becomes current. We store your email address, the category, area and chart you
         chose, and the priority date if you give one. Unsubscribe or delete your data with one click, in every email.
         <a href="/privacy/">Privacy</a>.</p>
       <div data-challenge data-sitekey="…"></div>
       <button type="submit">Send me the confirmation email</button>
       <p class="subscribe-status" role="status" aria-live="polite"></p>
     </form>
   </section>
   ```
3. Place it: bottom of `lineAreaPage` (hidden inputs for that line and area), the `/alerts/` page (selects for category and
   area), and the checker page under the result region (selects, prefilled by `check.js` from the current selection —
   the priority date field is **not** prefilled automatically; the visitor chooses to add it).
4. `src/client/subscribe.js`, loaded only on pages that have the form and only when `site.alerts` is set:
   - load the challenge provider's script **only when the visitor focuses the form** (not on page load);
   - on submit: client-side validation mirroring S-501, then `fetch(api + '/subscribe', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body })`;
   - success → replace the form with "Check your inbox for a confirmation email. Nothing is sent until you confirm.";
   - failure → "Could not sign you up right now. You can still follow new bulletins by feed." with a link to `/alerts/`.
5. Privacy page: when `site.alerts` is set add a section "Email alerts" stating exactly the stored fields from S-501,
   the 7-day purge of unconfirmed sign-ups, the email provider and the bot-challenge provider by category ("an email
   delivery service", "a bot-check service") with a note that the owner fills in the names, and the two ways to delete.
   Add a "Delete my data" form (email field → `POST /delete`).
6. `.env.example`: both variables with comments. `npm run check`.

## Tests to add

- With `alerts` set: the EB-2 India page contains the form with hidden `line=EB2` and `area=india`, the consent paragraph

## Acceptance
- [ ] No form and no challenge script anywhere unless both settings are present (test).
- [ ] Consent wording states what is stored and how to leave; success and error states work.
- [ ] The privacy page is updated in the same change as the form.
- [ ] The third-party challenge script loads only after the visitor interacts with the form.
- [ ] Verified against a local S-501 handler in its console-mailer mode (describe how in the logbook), or marked "not verified end to end".
- [ ] `npm run check` green; 375 and 1280, light and dark.

## Pitfalls
- A priority date tied to an email address is personal data. Keep it optional and never prefill it silently.
- Do not show "you are already subscribed": the API deliberately does not reveal that.
- The form must not block the page for visitors with JavaScript off: with no JavaScript, show a sentence pointing to the feed instead.
