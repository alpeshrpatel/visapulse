## Goal
The planner is the only page that loads React (about 52 kB gzip). Replace the React form with a build-time
rendered form plus a small plain script, keeping the rules engine and every behaviour identical.

## Before you start
Read the S-209 logbook entry. If the planner met its target (or Lighthouse was not run), **do not do this story**:
leave it `READY` and take the next one. The decision record is D30.

## Context
- `src/greenCardTimeline.js` exports `buildGreenCardPlan(input, bulletin)` → the plan object. It is pure. **Do not change it.**
- `src/GreenCardPlanner.jsx` (368 lines) holds: `initialInput` (all field names and defaults), `stageOptions`, the
  field visibility conditions, `updateInput` (special handling when `route` or `path` changes), and the result markup.
- `src/client/planner.jsx` mounts it. `plannerPage` in `src/site/pages.js` embeds the bulletin as JSON in `#planner-bulletin`.
- Styles: `src/client/planner.css` (class names `planner-…`).

## Files to touch
`src/site/planner.js` (new: build-time form markup), `src/client/planner.js` (new), `src/site/pages.js`,
`scripts/build-site.mjs`, `src/site/layout.js` (typedef only if an asset name changes), `package.json`,
`package-lock.json` (through `npm uninstall`), `test/site.test.js`, `docs/DECISIONS.md`.
Delete: `src/GreenCardPlanner.jsx`, `src/client/planner.jsx`.

## Steps
1. Before touching anything, record the current behaviour. In the preview, for each of these four inputs write down
   the "next step" title and the list of stage names and statuses shown:
   (a) defaults; (b) employment, adjustment, EB-2, India, priority date 2015-01-01, PERM certified, petition approved;
   (c) family preference, consular, F4, Philippines, priority date 2001-01-01, petition approved, case stage "documentReview";
   (d) immediate relative, adjustment, petitioner status citizen.
2. `src/site/planner.js`: export `plannerForm(plannerBulletin)` returning the whole form as `html` (same field `name`s,
   same option values and labels, same class names, same `<fieldset>`/`<legend>` grouping as the JSX). Every conditional
   block gets a `data-show-when="<condition id>"` attribute and is rendered always; the script hides those that do not apply.
   Add an empty `<div id="planner-result" aria-live="polite"></div>`.
3. `src/client/planner.js`: read the form into the same input object shape as `initialInput`; apply the same derived
   values the component computes (`categoryGroup`, effective `categoryCode`, resets when `route` or `path` changes);
   toggle `hidden` on `[data-show-when]` blocks; call `buildGreenCardPlan`; render the result with
   `document.createElement` (no `innerHTML`). Icons from `lucide-react` become text symbols with `aria-hidden="true"`
   (for example ✓, !, →, –, ?).
4. `scripts/build-site.mjs`: entry point `planner: 'src/client/planner.js'`; remove `jsx: 'automatic'` only if no `.jsx` remains.
5. `plannerPage`: replace `<div id="planner-root">…</div>` with `${plannerForm(plannerBulletin)}`; keep the JSON script and the `<noscript>` note.
6. `npm uninstall react react-dom lucide-react @types/react @types/react-dom`.
7. Repeat step 1 with the new page and compare field by field. Any difference is a bug in the new script.
8. Add decision D35 (supersedes D30). `npm run check`. Check 375/768/1280, light and dark.

## Pitfalls
- `supportDocsReady` is a three-state value (`'unknown'`, `true`, `false`) with special conversion in `updateInput`. Copy it exactly.
- When `route` is `familyImmediate` the component forces category `F2A` only as a placeholder and hides the category field.
- Checkbox fields are booleans in the input object, not the string `"on"`.
- `tsconfig.json` does not type-check `src/client/`. Be extra careful with typos; test in the browser.
