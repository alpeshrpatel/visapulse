# S-810 IndexNow: tell search engines about a new bulletin (owner-triggered)

| | |
|---|---|
| Status | READY for the code · sending is an owner action |
| Size | S |
| Difficulty | Careful |
| Phase | 7 Growth engineering |
| Needs | Site live with `SITE_URL` (to be useful) |
| Why (growth) | Bulletin-day searches peak within hours. IndexNow is an open protocol that lets a site notify participating search engines (Bing and others) that specific pages changed, instead of waiting for a crawl. Google does not use it; for Google the sitemap and Search Console remain the route. |

## Goal
A build setting that publishes the IndexNow key file, and a script that prepares — and, only when the owner
runs it with an explicit flag, sends — the list of pages that changed for a new bulletin.

## How IndexNow works (confirm against https://www.indexnow.org/documentation before coding; do not rely on this summary alone)
- The site hosts a text file at `https://<host>/<key>.txt` whose content is the key (8 to 128 characters: letters, digits, dashes).
- A JSON `POST` to `https://api.indexnow.org/indexnow` with `{ host, key, keyLocation, urlList }` reports changed URLs.
If the documentation you read differs from this, follow the documentation and note the difference in the logbook.
If you cannot open the documentation in this session, build only the key-file part and the dry run, and say so.

## Settings
`INDEXNOW_KEY` — public value; must match `^[A-Za-z0-9-]{8,128}$`; unset → no key file, and the script refuses to send.

## Files to touch
`scripts/build-site.mjs` (write `/<key>.txt`), `src/lib/indexNow.js` (new, pure), `test/indexNow.test.js` (new),
`scripts/indexnow.mjs` (new), `package.json` (`"indexnow": "node scripts/indexnow.mjs"`), `.env.example`,
`docs/RUNBOOKS.md` (RB9 bulletin day: one optional step).

## Steps
1. `src/lib/indexNow.js`:
   ```js
   /** @param {string} period @param {{ lines, areas }} vocabulary @returns {string[]} site paths that change when this period is added */
   export function changedPaths(period, vocabulary)
   /** @param {{ siteUrl: string, key: string, paths: string[] }} input @returns {{ host, key, keyLocation, urlList }} */
   export function indexNowPayload(input)
   ```
   `changedPaths`: `/`, the bulletin page for the period, the previous month's bulletin page (its "next" link changed),
   `/visa-bulletin/`, `/priority-dates/`, `/check/`, `/planner/`, every `/priority-dates/<line>/` and
   `/priority-dates/<line>/<area>/`; plus `/country/…` and `/next-visa-bulletin/` **only if** those URL helpers exist in
   `src/site/format.js`. Use the `urls` helpers; do not hard-code path strings.
2. Build: when `INDEXNOW_KEY` is valid, write `dist/<key>.txt` containing the key. Invalid value → the build fails with a message.
3. `scripts/indexnow.mjs`:
   - arguments: a period (default: newest in the data), `--send`;
   - requires `SITE_URL` and `INDEXNOW_KEY`; otherwise exit 2 with a message;
   - **default is a dry run**: print the endpoint, the URL count and the JSON payload, and end with
     "Dry run. Nothing was sent. The owner runs this with --send after deploying.";
   - with `--send`: first `fetch` the key file on the live site and stop if it does not return the key ("deploy first");
     then one `POST`; print the HTTP status; never retry automatically.
4. Tests: `changedPaths` contains the bulletin page and all 75 category × area pages and no duplicates; the payload's
   `urlList` entries all start with the site URL; `keyLocation` is `<siteUrl>/<key>.txt`; an invalid key throws.
5. `docs/RUNBOOKS.md` RB9: add "Optional, after the deploy is live: `SITE_URL=… INDEXNOW_KEY=… npm run indexnow` (dry
   run), then the same with `-- --send`. Owner only."
6. `npm run check`. Run the dry run once with made-up values (`SITE_URL=https://example.org INDEXNOW_KEY=abcdefgh12345678`)
   and paste the first lines of output into the logbook. **Never run with `--send`.**

## Acceptance
- [ ] With `INDEXNOW_KEY` set, the build publishes `/<key>.txt`; without it, nothing is added.
- [ ] `npm run indexnow` is a dry run by default and prints the payload.
- [ ] `--send` exists, checks the live key file first, and was **not** executed by the agent.
- [ ] Pure functions tested. RUNBOOKS mentions the optional step.
- [ ] `npm run check` green.

## Pitfalls
- Sending is an outward-facing action on the owner's behalf. An agent builds and dry-runs only.
- Do not submit URLs for a month that is not deployed yet; the `--send` path's key-file check is the guard.
- Do not submit the whole sitemap every time; only pages that changed.
