# S-609 Data API terms and stability

| | |
|---|---|
| Status | READY (most valuable once a third party actually uses `/data/`) |
| Size | S |
| Difficulty | Careful |
| Phase | 5 Scale and monetize |
| Needs | nothing to build; S-109 preferred so "verified" has one meaning |

## Goal
Developers, researchers and journalists will only build on `/data/` if they know what the fields mean and
that they will not change without notice. Document the format, publish a JSON Schema, promise a versioning
rule, and test our own records against the schema.

## Files to touch
`public/data/schema/bulletin-v2.schema.json` (new; copied to `dist/` as-is), `src/lib/jsonSchemaCheck.js` (new, small),
`test/schema.test.js` (new), `src/site/pages.js` (open-data page), `docs/ARCHITECTURE.md` (pointer to the schema).

## Steps
1. Write the JSON Schema (draft 2020-12) for one bulletin record, matching `src/lib/validateBulletin.js` and the
   "Schema v2" block in `docs/ARCHITECTURE.md`:
   - required: `schemaVersion` (const 2), `period` (pattern `^\d{4}-(0[1-9]|1[0-2])$`), `bulletin`, `source`, `areas`, `categories`;
   - `bulletin`: `month`, `year`, `fiscalYear`, `title`, `officialSourceUrl`;
   - `source`: `publisher`, `officialUrl`, `retrievedVia` (enum `web.archive.org`, `manual-file`), `sha256`
     (pattern 64 hex), `parserVersion` (integer), optional `snapshotUrl`, `snapshotTimestamp`;
   - `areas`: object of string → string, must contain `all`;
   - `categories`: `familySponsored` and `employmentBased`, each an object whose values have `label` and optional
     `finalActionDates` / `datesForFiling`, each an object of area key → value;
   - a cut-off value: `oneOf` [ISO date pattern, const `Current`, const `Unavailable`].
   Add `"$id"` as a relative path (`/data/schema/bulletin-v2.schema.json`) and a `description` on every property.
2. The published files in `/data/bulletins/*.json` also carry `verified` (boolean) added by the dataset layer. Include it
   as an optional property and describe it: "true when parsed from the official page whose archive snapshot and
   SHA-256 are recorded in `source`".
3. `src/lib/jsonSchemaCheck.js`: a **minimal** checker supporting only the keywords the schema uses (`type`, `const`,
   `enum`, `pattern`, `required`, `properties`, `additionalProperties` as a sub-schema, `oneOf`). About 60 lines.
   Do not add a dependency. If the schema needs a keyword the checker lacks, simplify the schema.
4. `test/schema.test.js`: every file in `data/bulletins/` passes the schema; a record with a bad period, a bad cut-off
   value, or a missing `source.sha256` fails.
5. Open-data page (`staticPages`), add sections:
   - **Format** — a short field list in prose with a link to the schema file.
   - **What "verified" means** — one paragraph (the sentence from step 2, plus a link to `/methodology/`).
   - **Stability** — "The `schemaVersion` field changes only when an existing field is removed, renamed or changes
     meaning. New optional fields may appear without a version change. A breaking change will be announced in the
     changelog at least 30 days before, and the previous version's files will stay available for 90 days."
     (Link the changelog only if S-608 is `DONE`; otherwise write "announced on this page".)
   - **Caching** — "Files change at most a few times a month. Please cache for at least an hour and avoid polling more
     than once a day; the feed tells you when a new month is added."
   - **Attribution** — "Not required. If you credit a source, 'Visa Bulletin data via VisaPulse, from the U.S.
     Department of State' with a link is appreciated."
   - **No warranty** — "The official bulletin is the authority. Check the `source` block of each record."
6. `npm run check` (the schema file is under `public/`, so `check-site` sees the link resolve).

## Acceptance
- [ ] A JSON Schema file is published at `/data/schema/bulletin-v2.schema.json` and linked from `/data/`.
- [ ] A test validates every record in `data/bulletins/` against it, with three negative cases.
- [ ] `/data/` documents fields, the meaning of "verified", the versioning promise, caching and attribution wording.
- [ ] No new dependency. `npm run check` green.

## Pitfalls
- The promise in "Stability" binds the project. Use exactly the wording above; do not promise uptime or support.
- The schema and `validateBulletin.js` must agree. If you find a difference, the validator is right; fix the schema and note it.
