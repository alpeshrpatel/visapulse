# S-705 Visa numbers used per fiscal year

| | |
|---|---|

| Difficulty | Expert |

## Goal
On each fiscal-year page, show beside the limit how many visas were actually issued or adjustments counted
per category and area, from the official annual tables — with provenance and caveats.

## Before you start
Read `docs/data/SOURCES.md` for the chosen source and S-704's code. This story **copies S-704's pipeline** for a second
dataset; if you find yourself designing something new, stop and re-read S-704.

## Design
- Manifest: `data/sources/usage-manifest.json`; records: `data/usage/<fiscalYear>.json`:
  ```json
  { "schemaVersion": 1, "fiscalYear": 2024, "title": "…as printed…", "source": { … }, "notes": ["…"],
    "issued": { "EB2": { "india": 0, "china": 0, "all": 0 }, … },
    "scope": "immigrant visas issued abroad" }
  ```
  `scope` is quoted from the table's own title (consular issuances only, adjustments only, or both). It is shown on the page.
- Parser `src/lib/parseUsage.js`, validator `src/lib/validateUsage.js`, fixtures in `test/fixtures/usage/`.

## Steps
1. Obtain one fiscal year's table by the approved route. Build the parser and a fixture test (five eye-checked numbers;
   throws on unknown labels).
2. Add the remaining years the source covers, one at a time, each through the manifest. A year the parser cannot read
   is skipped and listed in `docs/data/UNPARSED.md` under a "Usage" heading.
3. Fiscal-year page (`fiscalYearPage` from S-603): a new table per group "Visas issued in fiscal year <Y>": rows =
   lines, columns = the five areas where the source has that breakdown; a caption stating the scope exactly as the
   source words it, and the source link. If the source has no per-area breakdown for a line, show the worldwide figure only.
4. The limit column: show a limit only if it comes from an ingested official source (for example a limit printed in a
   bulletin of that fiscal year, quoted with its month). If no cited limit is available, omit the column. Never compute
   a limit from percentages yourself.
5. Caveat under the table, always: "Issued visas and cut-off dates measure different things. A fiscal year's issuances
   include cases with priority dates from many earlier years. These figures do not predict movement."
6. Methodology and open-data pages updated; validator wired into `npm run data:validate`. `npm run check`.

## Acceptance
- [ ] Per category and area, visas issued (or adjustments counted) for each fiscal year the official tables cover, each record with provenance.
- [ ] Shown on fiscal-year pages with the scope statement and the source link.
- [ ] A limit appears only with a citation; no computed limits.
- [ ] Unparsed years are listed, not guessed. Fixture tests exist.
- [ ] `npm run check` green.

## Pitfalls
- Consular issuances and USCIS adjustments are published by different agencies in different tables. Do not add them
  together unless a single official table already does.
- Country in these tables may be "foreign state of chargeability" or "nationality". Use only chargeability tables.
