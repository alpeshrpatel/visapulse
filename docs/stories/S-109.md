## Goal
The site should show only data parsed from the official page. The old third-party files stay in the
repository, frozen and unused by the build, and every "unverified" label disappears from the pages.

## Before you start
1. S-108 must be `DONE` in `docs/STORIES.md`.
2. Look for the owner's confirmation that the cross-check was reviewed: a line in `docs/LOGBOOK.md` or a ticked task in
   `TASKS.md`. If you cannot find one, set this story to `BLOCKED (owner: review docs/data/CROSSCHECK.md)` and stop.
3. Run `node -e "import('./src/lib/dataset.js').then(({loadDataset})=>{const d=loadDataset({officialDir:'data/bulletins'});console.log(d.periods.length, d.latestPeriod)})"`.
   If the newest verified period is older than the newest legacy month (`ls data/visa-bulletins/2026`), removing the
   fallback would make the home page go back in time. In that case stop and log it: S-110 (owner-saved pages) comes first.

## Context
- `scripts/build-site.mjs` calls `loadDataset({ officialDir, legacyDir })`. `legacyDir` is optional in `src/lib/dataset.js`.
- "Unverified" wording lives in: `verificationBadge` and `sourceLine` (`src/site/components.js`); `archivePage`,
  `lineAreaPage` (the "Status" column and the sentence under the chart), `checkPage` (`data.verified`),
  the methodology and open-data text in `staticPages` (`src/site/pages.js`); `src/client/check.js` (the "(unverified data…)" clause);
  the CSV column `verified` in `scripts/build-site.mjs`.
- `scripts/validate-data.mjs` checks that legacy files never change. **Keep that check.** `scripts/crosscheck.mjs` keeps reading legacy. Keep it.
- Tests in `test/site.test.js` and `test/dataset.test.js` load both directories.

## Out of scope
Deleting `data/visa-bulletins/` or `data/sources/legacy-freeze.json`. Changing `adaptLegacy` (leave the function and its tests; it is still used by tests and the cross-check).

## Files to touch
`scripts/build-site.mjs`, `src/site/components.js`, `src/site/pages.js`, `src/client/check.js`, `test/site.test.js`,
`test/dataset.test.js`, `docs/DECISIONS.md`, `docs/ARCHITECTURE.md`, `README.md`, `docs/LOGBOOK.md`.

## Steps
1. `scripts/build-site.mjs`: call `loadDataset({ officialDir: join(ROOT, 'data', 'bulletins') })` (no `legacyDir`).
   Keep the `verified` CSV column (it is part of the published format); it will always be `true`.
2. `src/site/components.js`: keep `verificationBadge` and `sourceLine` handling both cases (a defensive branch costs nothing),
   but nothing else changes there.
3. `src/site/pages.js`:
   - `archivePage`: lede becomes "`${dataset.periods.length}` months are available here, each verified against the official page.
     Months we could not parse link straight to the State Department." Remove the verified/unverified tag from each list item.
   - `lineAreaPage`: remove the "Status" column from the history table; the sentence under the chart becomes
     "This is what happened, not a forecast. Every month shown is verified against the official page." followed by `line.note`.
   - Methodology page: replace the "Verification status" paragraph with: "Every month shown on this site
     (`${dataset.periods.length}` months) is verified this way. Months the parser could not read with certainty are not shown;
     the archive links to the official page for those." Remove the sentence about the comparison with the older compilation
     from "How a month is checked" (step 3 of that list).
   - Open-data page: remove the sentence about unverified records.
4. `src/client/check.js`: the `data.verified ? '' : …` clause can stay (it will never fire).
5. Tests: in `test/site.test.js` change the dataset fixture to official-only and delete or rewrite assertions that
   look for an unverified month (`unverifiedPeriod`, `'not yet been checked'`). In `test/dataset.test.js` keep the legacy
   tests (they call `loadDataset` with `legacyDir` explicitly) and add one test: official-only dataset has
   `verifiedPeriods.length === periods.length` and `withheldPeriods.length === 0`.
6. Add decision **D34** to `docs/DECISIONS.md` (append a table row in the "Session 1 decisions" style):
   "The site build reads only `data/bulletins/`. Legacy data stays frozen in the repository and feeds only the cross-check.
   Supersedes D21 and D32." Why: official coverage is complete. Revisit: never.
7. Update `docs/ARCHITECTURE.md` (pipeline diagram line "dataset layer", the Layout block, "Debt and risks" item 1) and the
   "Where the numbers come from" table in `README.md`.
8. `npm run check`, then look at the home page, the archive, one category × area page and `/methodology/` in the preview.

## Pitfalls
- The archive page lists every month since 2002-01 and links to the official page when `dataset.get(period)` is null. That
  behaviour must remain for unparsed months.
- The home page uses `dataset.latestPeriod`. Confirm it is the newest published bulletin, not an older one (see "Before you start").
- The built-site check fails on the visible word `null`; make sure no template prints a missing value.
