## Goal
Four short explainers under `/learn/`, each answering one question in the bulletin's own terms, each sentence
cited, each linked from the places where the term appears on the site.

## The four pages
| Slug | Title | Source to quote |
|---|---|---|
| `priority-date` | What is a priority date? | The Visa Bulletin text on allotment "in the chronological order in which a petition… was filed" (fixture) and the USCIS page in `OFFICIAL_LINKS.uscisPriorityDates` (only if you could open it) |
| `final-action-vs-dates-for-filing` | Final Action Dates and Dates for Filing: what is the difference? | The bulletin's opening section (fixture): it defines both charts and says when USCIS allows the filing chart |
| `current-and-unavailable` | What do "C" (Current) and "U" (Unavailable) mean? | The bulletin's sentence defining "C" and "U" (fixture, just above the first table) |
| `retrogression` | What is retrogression? | The bulletin does not always define the word. Use only: our own data definition ("a cut-off date that is earlier than the previous month's") + a count from the dataset. No legal claim. |

## Rules
- Entries go in `EXPLAINERS` in `src/site/explainers.js` with `reviewedOn: null`.
- 150–350 words each. Quote the official sentence, then say it again in plain words. No advice, no examples about a
  particular person's case.
- Each page ends with "See it in the data": links to the checker, the latest bulletin and one relevant category × area page.
- `retrogression` shows a data line computed at build time: "In our data, the Final Action Date moved backwards in
  `<n>` of `<m>` month-to-month steps across all categories and areas." (count with `describeChange` over `dataset.series`
  for every `LINES` × `AREAS`). No other statistic.

## Files to touch
`src/site/explainers.js`, `src/site/pages.js` (conditional links), `test/explainers.test.js`.

## Steps
1. Write the four entries, one at a time, reading the source first.
2. Add the `/learn/` index content (already built by the framework when at least one explainer is published): one line per page.
3. Conditional links (`explainerLink`, empty until published):
   - "priority date" in the "How to read these dates" list on bulletin pages → `priority-date`;
   - the Dates for Filing panel help text → `final-action-vs-dates-for-filing`;
   - the same list's "Current / Unavailable" item → `current-and-unavailable`;
   - the "Retrogressions" heading on category × area pages → `retrogression`.
4. `SHOW_DRAFTS=1 npm run dev`; read each page against its source.

## Tests to add
- Each of the four entries validates; each rendered page has one `<h1>`, a "Sources" list and the disclaimer sentence.
- The retrogression page's count equals a count computed independently in the test.
- With the default build no page links to `/learn/` (nothing is published).

## Acceptance

- [ ] Word counts within 150–350; no advice; no predictions.
- [ ] Conditional links are in place and produce nothing until publication.

## Pitfalls
- Do not define "priority date" from memory with details about PERM filing dates or petition types unless the cited
  official page says so and you read it. If you could not open the USCIS page, the definition is limited to what the
  bulletin text says.
- These pages must not duplicate each other. One question per page.
