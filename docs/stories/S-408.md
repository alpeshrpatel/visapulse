# S-408 Pre-launch QA on the deployed preview

| | |
|---|---|
| Status | BLOCKED (owner deploys a preview and gives its address) |
| Size | S |
| Difficulty | Careful |
| Phase | 3 Launch |
| Needs | A preview deployment URL; a browser tool in the session; ideally S-209, S-403, S-404, S-407 `DONE` |

## Goal
Check the real deployed site before anyone is told about it: headers, crawler files, canonical links,
cross-browser rendering, and the launch gate in `docs/LAUNCH.md`.

## Owner part
1. Deploy `dist/` to the chosen host (RUNBOOKS RB4) with `SITE_URL` set to the **production** address.
2. Give the agent the preview address (for example `https://visapulse-preview.pages.dev`).
3. Do the two checks an agent cannot do: open the site in Safari and in Chrome on a phone.

## Agent part
Use the browser tool for pages and `curl -sI <url>` for headers (the site is the owner's own; no login is involved).
Record every result in the logbook as pass / fail / not checked.

| # | Check | Pass when |
|---|---|---|
| 1 | `curl -sI <preview>/` | `x-content-type-options: nosniff`, `x-frame-options: DENY`, `referrer-policy`, `permissions-policy` present |
| 2 | `curl -sI <preview>/assets/<any hashed file>` | `cache-control` contains `immutable` |
| 3 | `curl -sI <preview>/data/latest.json` | `access-control-allow-origin: *` |
| 4 | `<preview>/robots.txt` | allows all and names `Sitemap: <production>/sitemap.xml` |
| 5 | `<preview>/sitemap.xml` | well-formed; every `<loc>` starts with the production address; count equals the page count printed by the build minus one (404) |
| 6 | `<preview>/feed.xml` | well-formed Atom; newest entry is the newest bulletin |
| 7 | `<preview>/this-page-does-not-exist` | status 404 and the site's "Page not found" page |
| 8 | Home page source | `<link rel="canonical">` is the production address, not the preview address |
| 9 | Home, one bulletin page, EB-2 India, checker, planner | no console errors, no failed requests, correct at 375 and 1280, light and dark |
| 10 | Checker | a date equal to the cut-off reads "not current yet"; the fragment restores after reload |
| 11 | Link preview (if S-404 done) | `<preview>/og/default.png` shows readable text |
| 12 | Structured data (if S-407 done) | paste one page address into validator.schema.org in the browser tool: no errors |
| 13 | S-209 parts B and E repeated on the preview | results recorded |

Then open `docs/LAUNCH.md`, section "Gate before any promotion", and for each of the four gate items write
"met" or "not met: <reason>" in the logbook. Do not tick the gate yourself if any item is not met.

## Acceptance
- [ ] All 13 checks recorded with their result.
- [ ] Every failure either fixed (and re-checked after the owner redeploys) or listed as a launch blocker.
- [ ] Launch gate status written out item by item.
- [ ] Owner's Safari and phone checks recorded as done or still open.

## Pitfalls
- Never deploy, change DNS, or change host settings yourself.
- If the canonical link shows the preview address, `SITE_URL` was set wrongly at build time: report it; do not edit code.
- Do not submit the preview address to any search engine.
