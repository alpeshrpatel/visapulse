## Goal
`/learn/visa-bulletin-predictions/`: explain why VisaPulse publishes no predictions, point to the only
forward-looking statements that are official (the State Department's own notes inside a bulletin, when it
prints them), and show the last 12 months of actual movement for every line.

## Content (explainer entry, slug `visa-bulletin-predictions`, `reviewedOn: null`)
Title: `Visa Bulletin predictions: what can and cannot be known`
1. **Short answer** — "Nobody outside the State Department knows next month's cut-off dates. VisaPulse does not
   publish predictions. Here is what is actually knowable." (our own statement; no citation needed)
2. **Why predictions fail** — only reasons supported by the bulletin's own text (cite the fixture bulletin): cut-off
   dates are set each month from the numbers available and the demand reported; dates can be moved back
   ("retrogressed") or a category made unavailable. Quote the bulletin's sentences on how dates are established.
   Then one data sentence computed at build time: "In our data, the Final Action Date moved backwards in `<n>` of `<m>`
   month-to-month steps." (same count as S-802; reuse the function if it exists).
3. **What the State Department itself says** — "Some bulletins include a section in which the State Department
   comments on expected movement in the coming months. When it does, that is the only official forward-looking
   statement. Read it in the bulletin itself:" + link to the latest bulletin's official URL and the bulletin index.
   Do **not** summarise or restate any such note.
4. **What happened in the last 12 months** — a table generated from data for every `LINES` × `AREAS` pair:
   columns Category, Area, `<Month Year 12 months ago>`, `<latest Month Year>`, Change (`movementChip(describeChange(now, then))`).
   Rows where the earlier month is missing show "no data". Heading note: "This is history, not a forecast."
   Each row links to its category × area page.
5. **What you can do instead** — links: check your date (checker), follow new bulletins (`/alerts/`, only if that page
   exists), read how the line works (conditional explainer link).

The body function needs the dataset: use the `(cite, context)` signature (add `context = { dataset, site }` to the
framework if S-604 has not already).
