# S-112 Supply-chain hygiene

## Goal
Keep the small dependency set safe without manual effort: audit in CI, monthly grouped update pull requests,
third-party actions pinned to exact commits, and a stated Node version policy.

## Files to touch
`.github/workflows/ci.yml`, `.github/workflows/refresh-data.yml`, `.github/dependabot.yml` (new), `README.md`.

## Steps
1. `.github/workflows/ci.yml`: after `npm ci` add
   ```yaml
         - run: npm audit --omit=dev --audit-level=high
   ```
2. Create `.github/dependabot.yml`:
   ```yaml
   version: 2
   updates:
     - package-ecosystem: npm
       directory: /
       schedule: { interval: monthly }
       groups:
         all-npm: { patterns: ['*'] }
       open-pull-requests-limit: 2
     - package-ecosystem: github-actions
       directory: /
       schedule: { interval: monthly }
       groups:
         all-actions: { patterns: ['*'] }
   ```
3. Pin the two actions used in both workflows (`actions/checkout`, `actions/setup-node`) to full commit SHAs.
   Look the SHAs up; **never type one from memory**:
   ```bash
   git ls-remote --tags https://github.com/actions/checkout 'v4*' | tail -n 3
   git ls-remote --tags https://github.com/actions/setup-node 'v4*' | tail -n 3
   ```
   Take the SHA of the newest exact `v4.x.y` tag (if a line ends in `^{}` use that line's SHA) and write, for example,
   `uses: actions/checkout@<40-character sha> # v4.x.y`.
   If the lookup fails (no network), leave the `@v4` references, leave this acceptance box unticked and say so.
4. `README.md`: under "Commands" add: "Node policy: the major version in `.nvmrc`. CI uses the same file. Raise it only
   together with `engines.node` in `package.json`."
5. Run `npm audit --omit=dev --audit-level=high` locally and paste the result summary into the logbook.
6. `npm run check`.

## Acceptance
- [ ] CI runs the audit and fails on high or critical findings in runtime dependencies.
- [ ] `.github/dependabot.yml` exists with monthly grouped updates for npm and GitHub Actions.
- [ ] Both workflows reference actions by 40-character SHA with a version comment (or the box is unticked with the reason).
- [ ] README states the Node policy.
- [ ] `npm run check` green; local audit result logged.

## Pitfalls
- YAML indentation in the workflow files is two spaces under `steps:`; a wrong indent breaks the whole workflow and nothing
  local will tell you. Compare your change with the lines around it.
- The workflows have never run (the repository is not pushed). You cannot test them; say so in the logbook.
- If the audit reports a high finding, do not run `npm audit fix --force`. Log the finding and the package; the owner decides.
