# S-407 Structured data for search engines

## Goal
Help search engines show breadcrumbs for our pages and recognise `/data/` as a dataset, using JSON-LD.
Structured data needs absolute addresses, so it is emitted only when `SITE_URL` is set.

## Files to touch
`src/site/layout.js`, `src/site/structuredData.js` (new, pure), `src/site/pages.js`, `test/site.test.js`.

## Steps
1. `src/site/layout.js`: the `jsonLd` parameter currently takes one object. Accept `object | object[] | undefined`
   and emit one `<script type="application/ld+json">` per object (keep using `jsonForScript`).
2. `src/site/structuredData.js` (`// @ts-check`):
   ```js
   /** @param {string | null} siteUrl @param {{ name: string, path: string }[]} trail @returns {object | null} */
   export function breadcrumbList(siteUrl, trail)
   /** @param {string | null} siteUrl @param {{ periods: number, first: string, last: string }} facts @returns {object | null} */
   export function datasetJsonLd(siteUrl, facts)
   ```
   Both return `null` when `siteUrl` is null.
   - `breadcrumbList`: `{"@context":"https://schema.org","@type":"BreadcrumbList","itemListElement":[{"@type":"ListItem","position":1,"name":…,"item":"<siteUrl><path>"}, …]}`.
   - `datasetJsonLd`:
     ```json
     { "@context": "https://schema.org", "@type": "Dataset",
       "name": "U.S. Visa Bulletin cut-off dates, <first> to <last>",
       "description": "Monthly priority-date cut-offs for family-sponsored and employment-based preference categories, parsed from the U.S. Department of State Visa Bulletin, with provenance for each month.",
       "url": "<siteUrl>/data/",
       "isAccessibleForFree": true,
       "license": "<siteUrl>/data/#license",
       "creator": { "@type": "Organization", "name": "VisaPulse", "url": "<siteUrl>/" },
       "isBasedOn": "https://travel.state.gov/content/travel/en/legal/visa-law0/visa-bulletin.html",
       "temporalCoverage": "<first>/<last>",
       "distribution": [
         { "@type": "DataDownload", "encodingFormat": "text/csv", "contentUrl": "<siteUrl>/data/cutoffs.csv" },
         { "@type": "DataDownload", "encodingFormat": "application/json", "contentUrl": "<siteUrl>/data/latest.json" } ] }
     ```
3. Breadcrumb trails (first item always `{ name: 'VisaPulse', path: '/' }`):
   - bulletin page (not home): Home → `Visa Bulletin archive` (`/visa-bulletin/`) → `<Month Year>`;
   - line page: Home → `Priority dates` → `<code>`;
   - line × area page: Home → `Priority dates` → `<code>` → `<code> <area>`.
   Pass the result as `jsonLd` (filter out nulls; the home page keeps its `WebSite` object).
4. Open-data page: give the first paragraph `id="license"` and make it say plainly: "The cut-off dates are U.S.
   government data in the public domain. Our structured copies may be used freely, with or without attribution."
   Pass `datasetJsonLd(...)` for that page (the `page()` helper in `staticPages` needs an optional `jsonLd` argument).
5. `npm run check`.

## Tests to add (`test/site.test.js`)
- With the default `site` (no URL): bulletin, line, line × area and data pages contain **no** `BreadcrumbList` and no `"Dataset"`.
- With `liveSite`: the EB-2 India page contains a `BreadcrumbList` whose last item is `https://example.org/priority-dates/eb2/india/`
  and whose positions are 1, 2, 3, 4; every JSON-LD block on the page parses with `JSON.parse`.
- With `liveSite`: the data page contains `"@type":"Dataset"` and both `contentUrl`s.

## Acceptance
- [ ] BreadcrumbList on bulletin, category and category × area pages; Dataset on `/data/`; only with `SITE_URL`.
- [ ] Every emitted block is valid JSON with absolute `https` addresses.
- [ ] The licence statement exists at `/data/#license` and matches the JSON-LD `license` value.
- [ ] `npm run check` green.
- [ ] Logbook notes that the Schema.org validator and Google's Rich Results Test were **not** run by the agent
      (they need the live site) and lists them under "Owner actions" for S-408.

## Pitfalls
- Do not add `FAQPage`, `Article`, `Review` or rating markup. Markup that does not match visible content is treated as spam.
- `jsonForScript` already escapes `<`; do not build JSON by string concatenation.
- The home page is a bulletin page with `isHome`; it must not get a breadcrumb.
