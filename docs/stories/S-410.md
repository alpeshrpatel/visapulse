# S-410 Thirty-day review

| | |
|---|---|
| Status | READY 30 days after launch |
| Size | S |
| Difficulty | Careful |
| Phase | 3 Launch |
| Needs | Site live for 30 days; S-403 and S-409 done; the owner's exports |

## Goal
Decide what to build and promote next from evidence instead of opinion. Produce a one-page review and
re-rank the backlog.

## Inputs the owner provides (put them in `docs/growth/exports/`)
- Search Console: Performance export (queries and pages, last 28 days) and the Pages (indexing) export.
- Analytics: top pages, referrers and daily visits for the last 30 days (CSV or pasted numbers).
- Counts: feed subscribers (if the host or a feed service shows them), feedback messages and corrections received.
- A note of what was posted where and on which dates (the "Posting log" table in `docs/growth/METRICS.md`).

If an input is missing, write "not provided" in that part of the review. Do not estimate it.

## Steps
1. Read the exports. Compute, by page type (`/` home, `/visa-bulletin/*`, `/priority-dates/*/*`, `/priority-dates/*`,
   `/check/`, `/planner/`, other): impressions, clicks, click-through rate, average position.
2. Find the bulletin-day effect: visits on the day a bulletin page was added and the two days after, against the daily average.
3. List the ten queries with the most impressions where our average position is 5–20, and the page each lands on.
4. List referrers with more than five visits, and match them to the posting log.
5. Write `docs/growth/reviews/<YYYY-MM>-30-day.md` with these headings:
   **Numbers** (the table from step 1), **What worked**, **What did not**, **Surprises**, **Corrections received**,
   **Decisions** (three at most), **Next three stories** (ids from `docs/STORIES.md` with one line of evidence each).
6. Update the monthly table in `docs/growth/METRICS.md` with the month's numbers.
7. In `docs/STRATEGY.md`, section "Feature bets": append a dated line "Re-ranked <date> from the 30-day review: …"
   (do not rewrite history above it).
8. Move the three chosen stories to the top of the ready queue in `docs/STORIES.md`.

## Acceptance
- [ ] Review file exists with every heading filled or marked "not provided".
- [ ] Every claim in "What worked / did not" points to a number in the exports.
- [ ] `docs/growth/METRICS.md` monthly table updated.
- [ ] STRATEGY has the dated re-ranking line; the ready queue in STORIES reflects the three chosen stories.

## Pitfalls
- Thirty days of a new site is a small sample. Say "too early to tell" where it is; do not draw trends from single digits.
- Do not include any individual visitor's data. Aggregates only.
