# S-111 Data freshness guard

## Goal
A static site can go stale without anyone noticing. Make staleness visible in three places: the validator
prints the newest verified month, the scheduled workflow fails when a month is overdue, and every page footer
says "Data through <Month Year>".

## Rule (decide nothing yourself; implement exactly this)
The bulletin for month M+1 is published during month M. So on any day in month M:
- the record for **M** must exist;
- after the **25th** of month M, the record for **M+1** must exist too.

`expectedLatestPeriod(today)` = the period of `today`, or the following period when the day of the month is 26 or later.
"Record" means a verified record in `data/bulletins/`.

## Files to touch
`src/lib/freshness.js` (new), `test/freshness.test.js` (new), `scripts/validate-data.mjs`, `scripts/build-site.mjs`,
`src/site/layout.js`, `test/site.test.js`, `.github/workflows/refresh-data.yml`, `docs/RUNBOOKS.md`.

## Steps
1. Create `src/lib/freshness.js` (`// @ts-check`, imports from `./period.js`):
   ```js
   /** @param {string} today ISO date YYYY-MM-DD (UTC) @returns {string} period */
   export function expectedLatestPeriod(today)
   /**
    * @param {string | null} latestVerified period or null @param {string} today ISO date
    * @returns {{ expected: string, latest: string | null, monthsBehind: number, fresh: boolean }}
    */
   export function freshness(latestVerified, today)
   ```
   `monthsBehind` = number of months from `latest` to `expected` (0 when equal or newer; when `latest` is null use `Infinity`).
   `fresh` = `monthsBehind === 0`. No `new Date()` without an argument anywhere in this file: "today" always comes in.
2. `test/freshness.test.js`: cover `2026-11-25` → `2026-11`; `2026-11-26` → `2026-12`; `2026-12-26` → `2027-01` (year boundary);
   `2027-01-01` → `2027-01`; `freshness('2026-11', '2026-11-20')` fresh; `freshness('2026-11', '2026-11-27')` 1 behind;
   `freshness('2026-12', '2026-11-27')` fresh; `freshness(null, …)` not fresh.
3. `scripts/validate-data.mjs`: after the official-records loop, compute the newest period among `officialFiles`
   and `freshness(newest, new Date().toISOString().slice(0, 10))`. Print
   `Newest verified period: <period> (expected <expected>)`. When not fresh:
   - default: `console.warn('Warning: data is <n> month(s) behind.')` and continue;
   - with the flag `--strict-freshness`: add it to `errors` so the script exits 1.
4. `scripts/build-site.mjs`: add `dataThrough: formatPeriod(latest)` to the `site` object. Add `dataThrough: string` to the
   `SiteContext` typedef in `src/site/layout.js`. In the footer `fineprint` paragraph write
   `Data through ${site.dataThrough}. Cut-off dates are U.S. government data in the public domain. Site built ${site.buildDate}.`
5. `test/site.test.js`: add `dataThrough: 'November 2026'` to the `site` fixture and assert one rendered page contains
   `Data through November 2026`.
6. `.github/workflows/refresh-data.yml`: change the cron to `'17 14 8-28 * *'` and add a last step that always runs:
   ```yaml
         - name: Freshness gate
           run: node scripts/validate-data.mjs --strict-freshness
   ```
7. `docs/RUNBOOKS.md` RB2: add one line: "After the 25th the scheduled workflow fails if next month's record is missing;
   add the month (step 1 or 2) to clear it."
8. `npm run check`.

## Acceptance
- [ ] `expectedLatestPeriod` and `freshness` are pure and take the date as a parameter.
- [ ] Tests cover the 25th/26th boundary and the December → January boundary.
- [ ] `npm run data:validate` prints the newest verified period and only warns when behind.
- [ ] `node scripts/validate-data.mjs --strict-freshness` exits 1 when behind (today it will: say so in the logbook).
- [ ] Every page footer shows "Data through <Month Year>".
- [ ] Workflow has the freshness step; RUNBOOKS mentions it.
- [ ] `npm run check` green (the gate uses the non-strict mode, so it stays green).

## Pitfalls
- Until the owner's backfill and S-110, the newest *verified* month is far behind, so the strict mode fails. That is correct
  and expected; do not weaken the rule. Note it under "Owner actions" in the logbook.
- "Data through" uses `dataset.latestPeriod` (what the site actually shows), not the newest verified month.
- Do not call the clock inside `src/lib/`. Only the scripts read today's date.
